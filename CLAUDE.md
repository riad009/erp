# Khata App — notes for Claude (read this first)

Bangla bookkeeping app for **কাজী রোমান এন্ড ব্রাদার্স** (steel coil / sheet trader, Dhaka).
Tabs (this order on phone AND computer — owner's wish): দৈনিক · মেমো · স্টক · খতিয়ান · বাকি লিস্ট · কোম্পানি · মালের খতিয়ান · লেবার · ড্যাশবোর্ড · সেটিং · অ্যাক্টিভিটি · অ্যাডমিন (+ 👤 account button last).

## How the owner wants to work
- Talk in **easy English**, short answers; the app UI is **Bangla** (Bangla digits ০-৯).
- He sends a screenshot + a short request → make the change → **test on computer (1440) and phone (390)** → tell him in a few lines what changed.
- After any change: `npm run dev`, open http://localhost:3000, log in, check the page, no console errors. Test against a local MongoDB (`.env.local` `MONGO_URI=mongodb://127.0.0.1:…`, `MONGO_DB=khata_test`), never the live one (Atlas is not reachable from the cloud sandbox anyway).
- **Always publish every change right away**: commit and `git push origin main` — Vercel auto-deploys `main` to the live site https://erp-psi-woad.vercel.app in ~1 min. Never leave a change only on this computer. Then tell him to refresh.

## Data
- **MongoDB** via `app/api/db/route.ts` + `lib/store.ts` (+ `lib/mongo.ts`, env `MONGO_URI`, `MONGO_DB` default `khata`). The app still uses its old paths; `lib/store.ts` maps them to clearly named collections, one record per item, fields stored directly:
  `stock_days` (days/<date>) · `stock_markas` + `stock_sizes` (settings/cats; sizes stored as `height`, `width`, `open_kg`, `buy_rate`, `mark` (only K = green now; the old B red mark was removed on purpose — don't bring it back), `marka_id`, `position` = order added) · `parties` (ledgers) · `companies` · `expenses` (khoroch) · `cash_opening` (amdani/sabek, one per date) · `settings` (`sale_rates`, `labour_rate`).
  The first layout (`{_id, data}` in days/ledgers/settings…) is moved over automatically on the first request (`migrateOldLayout`). Open `/api/db` (logged in) to see record counts.
- Browser side: `public/khata/db.js` gives the same small API the app had on claude.ai (`collection(n).get()`, `doc('col/id').get()/set()/delete()`); `getDB()` in index.html uses it. On an empty database it first uploads that browser's localStorage. If the server can't be reached → `null` → app works from localStorage only.
- **Offline-safe saving (owner: nothing typed may be lost)** — `public/khata/db.js`: every `doc.set/delete` goes into an outbox in localStorage (`kg-khata-outbox`, one item per record, latest wins) and is sent at once; no internet → it waits and is sent by itself (`online` event, every 8 s, on page open before the tabs read). Reads use a cache (`kg-khata-dbcache`) when offline, with waiting saves laid on top. When sending, if another device changed the same record since (from `changes` rows with another `cid`) the two are merged: lists of `{id}` lines joined by id, this device wins, lines it deleted (vs `base` = the record before its change) stay deleted; `map` objects joined. Merged result is shown via `onMerged` → live-sync `applyRemote`. Live sync skips records still waiting. Screen: only when offline — bottom strip "📴 ইন্টারনেট নেই — Nটা সেভ এই ডিভাইসে রাখা আছে…" + an alert toast on the first offline save. Sending happens quietly: no "অনলাইনে তোলা হচ্ছে / উঠে গেছে" badges (owner removed them — don't add back). (A page can't be *opened* with no internet — no service worker yet.)
- Sync safety (older, still there): a failed online save shows "⚠️ অনলাইনে সেভ হয়নি" (`saveFailed`); on load, entries/parties that are in this browser's copy but not online (last 21 days) are kept in `kg-khata-unsynced` and a bottom bar offers "⬆ অনলাইনে তুলুন" (merges them in, renumbers a clashing memo no.) or "বাদ দিন". No online connection → "⚠️ অনলাইনে যুক্ত নেই" bar.
- **Login (owner asked for it, Nov 2026):** `proxy.ts` sends anyone without the `khata_s` cookie to `/login` (`app/login/page.tsx`); API calls get 401 and `db.js` then opens /login.
  - `lib/auth.ts`: users in the `users` collection (`email`, `name`, `pass` = scrypt hash, `role` admin|user, `perms` = tab ids + `activity` + `undo`, `active`, `ver`). Cookie = signed {user, ver, expiry} (secret = `AUTH_SECRET` or derived from `MONGO_URI`); every API call re-checks the user, so a new password / switched-off user ends old logins. 8 wrong tries → 10 min wait. Stays logged in (owner: never ask again): cookie lasts 365 days and is renewed on every visit (GET /api/auth); the page also keeps a copy in localStorage `kg-khata-tok`, and /login uses it (`op:'resume'`) to log straight back in when an in-app browser loses the cookie. Logout clears both. `/khata/*` is sent with `Cache-Control: no-store` (next.config.mjs) so phones never show an old app.
  - First super admin is seeded on an empty `users` collection: admin@gmail.com / 1234 (owner's choice; he can change it via 👤 → পাসওয়ার্ড বদলান. He asked to remove the "change password" reminder pop-up and warning — don't add them back). Never put another real password in the repo (it is public).
  - Client: `/api/auth` GET → `window.__me`, `window.__allowedTabs`; tabs he may not see are hidden (`body.auth-wait` hides everything until then). Permissions are per tab (client-side); admin-only things (users, email, `import`) are checked on the server.
- **👑 অ্যাডমিন tab** (`/api/admin`, admin only): create / edit / switch off / delete users, tick which পাতা each may see; ✉️ প্রতিদিনের ইমেইল settings (on/off, recipient list, sender Gmail + Gmail **app password**, stored in `settings` `_id:'email_config'`; env `SMTP_USER`/`SMTP_PASS`/`SMTP_HOST`/`SMTP_PORT` override), "এখনই একটা পাঠান (টেস্ট)".
- **Nightly email** (`vercel.json` cron `59 17 * * *` = 11:59 pm Dhaka → `/api/cron/daily-email`, `lib/report.ts` `dayRecord` + `htmlSummary`): the whole day category by category, computed exactly like the app (owner checked it against his pages): 💵 নগদ (সাবেক জমা — hand-typed or carried like `sabekInfo` — + জমা − খরচ = হাতে নগদ) · এক নজরে · 🧾 মেমো (type kg × দর, sizes, লেবার, মোট) · 💰 জমা (via, ref) · 💸 খরচ (খুচরা marked) · 🚚 মাল এসেছে (গাড়ি, **company**, চালান, মার্কা/সাইজ, কেজি, **দর, টাকা** from the linked company চালান `co`/`ce`) · 📦 মাল গেছে (memo picks + হাতে বের) · 📊 স্টক (same walk as `itemStats`: আগের মোট / এসেছে / গেছে / মোট, + by মার্কা) · 🏭 কোম্পানি (today's চালান / টাকা দেওয়া, অবশিষ্ট before → after) · 📒 parties changed today (আগের বাকি → এখন বাকি) + সব পার্টির মোট বাকি. **No activity in the email** (owner). Attachment: only `khata-<date>.json` (all of that + `raw` = the day's records as saved) — the full backup is 👑 অ্যাডমিন → ⬇ ব্যাকআপ. At most once a day (`lastSent`); with `CRON_SECRET` set on Vercel only Vercel can call it.
- **🔄 Live sync (owner: "refresh kora na lage")**: every open page asks `/api/db` `{op:'changes', since}` every 6 s (and on focus) → the records other pages changed (from the `activity` log; own saves skipped via the `x-khata-client` page id from db.js) → re-reads only those and calls `__stock.remote` / `__company.remote` / `__ledger.remote` / `__labourRemote`, then repaints the open tab. It waits while someone is typing (focused box or typed-but-unsaved value) or a pop-up is open. A new feature that keeps its own copy of data must get a `remote` hook too.
- **📝 অ্যাক্টিভিটি tab** (`/api/activity`, `lib/activity.ts`, `lib/undo.ts`, collection `activity`): every `/api/db` set/delete is logged with the user's name, a Bangla summary (＋/－/✎ lines), the record before (`before`) **and after** (`after`) the save. Also login/logout, user changes, email sent, import (those get no buttons).
  - **Owner's মুছুন / ফেরান** (op `toggle`): a data card shows only **🗑 মুছুন** → takes *this one change* out of the app (`applyChange(cur, after, before)`: only the lines / fields this save touched, matched by id — or ts+item for stock lines — so later changes to the same party/day stay) → card **red dotted**, lines crossed out, "মুছে ফেলা হয়েছে — who · when", button **↶ ফেরান** → puts it back (`applyChange(cur, before, after)`) → card **green dotted**, "আবার ফেরানো হয়েছে", button 🗑 মুছুন again; repeatable. - Memo form লেবার টাকা is editable (`#fLabAmt` → `labMan`; saved `labourManual:true`, total = মাল + that লেবার, no rounding); ↺ goes back to the কেজি-based amount. The memo pop-up has "✕ বাতিল" in its top-right corner (`#fCancelTop`); the bottom বাতিল is hidden.
- Memo form তারিখ box is clickable (opens the calendar, also when editing a memo); a changed date moves the memo and its stock-out (`confirmedOn`) to that date.
- Memo form অগ্রীম / বাকী are editable boxes (`#fAdvAmt` / `#fDueAmt` → `advMan` / `dueMan`, saved as `memoAdv` / `memoDue`, ↺ back to auto). Typing অগ্রীম makes বাকী = মোট + আগের বাকি − অগ্রীম. They only change what the memo paper shows — the খতিয়ান balance is not touched.
- মাল picker (মার্কা → সাইজ pop-up) has a search box on the first screen: type মিলি (height) / লম্বা / "৬৫x৯১৪" → matching sizes from every মার্কা.
- মেমো tab date pill is clickable (`#mDay`): pick a day → only that day's memos (+ "↩ এই মাসের সব মেমো" back to the month list, the default); "নতুন মেমো" from there starts on that picked day (`newMemo(aid, day)`).
- **মেমো = মাল বিক্রি only.** টাকা জমা (from খতিয়ান or দৈনিক → নতুন জমা) gets no memo number and never shows in the মেমো tab — it is only in খতিয়ান / দৈনিক.
- Saving a memo = the goods leave the stock right away (no "মাল পাঠান / গেছে / ফেরান" buttons anywhere), even when a size is short (stock stops at ০).
- লাভ = (বিক্রি দর − কেনা দর) × কেজি per size; কেনা দর = size ✎ value, else latest কোম্পানি চালান দর (per কেজি — owner changed it from per টন in Nov 2026; amount = কেজি × দর). লেবার is not profit. Memo stores the cost of that day.
- 🏭 কোম্পানি খতিয়ান = like the owner's paper book: তারিখ | বিবরণ | জমা (টাকা দিয়েছি) | খরচ (মাল এসেছে) | অবশিষ্ট; আগের জের on top, oldest → newest, মোট last. অবশিষ্ট = আগের জের (`opening`, + = টাকা আগে দেওয়া) + জমা − খরচ (negative = কোম্পানি পাবে, red "বাকি"). চালান বিবরণ = "(৬০ × ৯১৪) মাল = কেজি × দর". On a phone the date sits on top of বিবরণ so all 3 money columns fit. The table box scrolls by itself (`fitTable`: fills the screen, page doesn't scroll on a computer), opens at the bottom (newest + মোট), column names and the মোট row stay fixed; a re-render keeps the scroll place. All চালান দর (stock মাল আসছে form + company form) are **per কেজি** (amount = কেজি × দর).
- 📦 **মালের খতিয়ান** tab (`#malkhata`, under কোম্পানি; owner's paper stock book): 4 tiles (আগের জের · মোট এসেছে · মোট গেছে · এখন অবশিষ্ট) + table তারিখ | বিবরণ | মাল এসেছে (জমা) | মাল গেছে (খরচ) | অবশিষ্ট, oldest → newest. আগের জের = Σ sizes' শুরুর কেজি; one row per গাড়ি per day (গাড়ি নং, মার্কা(s) with kg, company · চালান); one row per day of sales (party names "A / B / C", হাতে বের, kg actually taken, "N কেজি স্টকে ছিল না" when billed over stock). Computed by `__stock.malLedger()` with the same never-below-০ walk as `itemStats`, so the last অবশিষ্ট = মোট স্টক. Scroll box like কোম্পানি (opens at the bottom, sticky head / মোট). Visible to users with the `malkhata` tick or with স্টক.
- দৈনিক: 3 tiles (সাবেক জমা + নিট = হাতে নগদ), then আমদানি | খরচ | বিক্রয় columns; adding happens in pop-ups.
  - নতুন জমা has কার মাধ্যমে (`via`) + optional রেফারেন্স (`ref`) on the জমা entry, shown in আমদানি list and খতিয়ান. After a party is chosen a box shows its **আগের বাকি** and, once টাকা is typed, **জমার পর বাকি** (`#aPrevDue`).
  - খরচ column has a 💰 বিবিধ খরচ (খুচরা) card: items saved in the same day's khoroch list with `misc:true`; the main খরচ list shows them as one auto line "বিবিধ খরচ (খুচরা)" = their sum (totals already include them).
